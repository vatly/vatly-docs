`vatly.checkout_builder(profile)` handles one-off and mixed carts. Call
`.with_items([{"id": product_id, "quantity": 2}])`; repeated calls append detached
copies. `vatly.subscribe(profile).to_plan(plan_id).with_quantity(3)` creates a
single-plan checkout builder. Trial methods are `with_trial_days` and
`with_trial_ends_at(aware_datetime)`, rounded up to whole days. Quantity and trial
days must be positive integers. No request occurs until `await builder.create()`.

Both builders offer `with_redirect_url_success`, `with_redirect_url_canceled`,
`with_locale`, `with_metadata`, `with_billing_address`, `in_testmode`, and
`in_live_mode`. Mode methods assert the key's mode; they cannot change it.
`payload(overrides)` returns a deep detached wire-format dictionary.
`create(overrides, options=RequestOptions(...))` returns a full SDK Checkout plus
`get_url()`. Subscription builders replace rather than accumulate their plan item.

Use `.for_entity(EntityRef("team", authorized_team_id))` with `checkouts` wiring to
save ownership locally. A profile's `vatly_id` selects billing identity, not entity
ownership. Authorize all overrides on the server. Persist a purchase ID before
calling the API and reuse its idempotency key if the API or local save times out.
If local persistence fails after the API succeeds, retry with that **same key**.
Never blindly issue a second purchase. SDK auto-keys cover internal retries only.

Checkout redirects do not prove payment. Use signed events and reconciliation.
Checkout objects stay lean: read lines from checkout.order_id's Order, not from
invented checkout.products fields. [Subscriptions](/packages/fluent-python/subscriptions) covers old
plan references and the pending core order-line change.
